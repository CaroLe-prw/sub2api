# 内置 QQ 群渠道机器人

入口：**管理员后台 → 系统设置 → 通知 → QQ 群渠道机器人**。

此功能直接运行在 Sub2API 后端，使用 QQ 官方 WebSocket 网关。
升级部署当前代码构建的 Sub2API 镜像即可，不需要新增 Docker 容器、开放入站端口或配置回调域名。
现有已部署的旧镜像不会自动获得本功能。

## 配置步骤

1. 在 QQ 官方机器人管理端保持 **WebSocket** 接入模式，准备 AppID、AppSecret。
2. 更新 Sub2API，进入上述设置页，填写凭据、打开开关并保存。
3. 约 5 秒后点击“刷新连接状态”；正常应显示“已连接 QQ”。
4. 按 QQ 平台的开发体验/沙箱和服务范围要求将机器人加入群里。
5. 在群内发送 `@机器人 绑定信息`。尚未绑定的群只允许这个命令。
6. 将回复的群 OpenID 填入“允许查询的群 OpenID”；它不是数字 QQ 群号。
7. V2 模式勾选群成员可以查看的 Sub2API 分组，保存后发送 `@机器人 渠道状态`。

不会查询每个 QQ 群成员的 Sub2API 账户权限：允许的 QQ 群成员均能查看选定范围，
管理员只应选择可以公开到群里的分组。所有配置群共享同一展示范围。

## 指令

需要免 @ 查询时，请使用群主账号在**手机 QQ 群内**打开机器人的资料页，进入右上角设置，
查找“允许查看所有消息／接收所有消息”等消息范围选项；具体入口和可用性随 QQ 版本而异。
这不是开发者网页中选择 WebSocket/Webhook 的页面。授权后，在 Sub2API 的 QQ 机器人设置中打开
“免 @ 查询”并保存。在已允许的群里直接发送 `渠道监测`、`渠道状态`、`渠道监测 OpenAI` 即可。
`渠道监测` 是 `渠道状态` 的别名，也支持 `@机器人 渠道监测`。
此开关默认关闭；平台没有下发 `GROUP_MESSAGE_CREATE` 时，仅打开本站开关也无法收到未 @ 的消息。
普通聊天忽略，不保存聊天内容；绑定和即时检测仍使用 @ 指令。全量消息与 @ 消息沿用同一套消息去重。
QQ 官方全量群消息事件使用与现有连接相同的 `GROUP_AND_C2C_EVENT (1<<25)` 订阅。

| 指令 | 作用 |
| --- | --- |
| `@机器人 渠道状态` | V2 默认返回分组卡片看板图片，含缓存率、可用率、首 Token 和历史状态条 |
| `@机器人 渠道状态 名称` | 图片按平台或分组名称筛选 |
| `@机器人 渠道状态文字 名称` | 使用原有文字摘要，可按分组或模型名称筛选 |
| `@机器人 检测 编号` | V1 手动检测；需开启实测并配置成员 OpenID，可能产生模型调用费用 |
| `@机器人 绑定信息` | 查看当前群和发言成员的 OpenID |
| `@机器人 帮助` | 显示指令说明 |

也支持 `/渠道状态` 等前缀。普通聊天不会触发查询，不调用语言模型，不定时播报。
不会更改原有渠道监控任务的执行频率。

- **V1**：只展示已启用且已公开的监控，可以进一步按监控编号限制。配额检查会单独标注。
- **V2**：显示所选分组最近 90 分钟的已有汇总，不代表刚刚调用了模型；不提供即时实测。
- 图片与网页默认的“平台 / 分组”卡片使用相同矩阵及指标口径，每格 5 分钟，保留无数据的灰色格。
  每张图最多 12 张分组卡片，最多 4 张图片；超出 48 个分组会在图上提示按名称筛选。
- 后台的“预览已保存的看板”使用保存后的范围，不发送 QQ 消息，可翻页查看。
- PNG 由后端直接绘制，Docker 镜像已增加 `font-noto-cjk` 中文字体，不需要浏览器或额外容器。
  使用二进制部署时请安装 Noto CJK，或通过 `QQ_BOT_FONT_PATH` 指定包含中文的 TTF/OTF/TTC 字体，安装后重启服务。
- 图片直接使用 QQ 官方预上传、分片 PUT、完成合并接口上传，再以富媒体被动回复发送。
  无需配置公网图片域名，文件上传不会主动向群发送消息。
- 看板先发送一条 Markdown 格式的 @ 发起人提示，再发送原生图片。
  @ 使用原消息中的成员 OpenID；免 @ 查询和 @ 查询一致。提示使用序号 1，
  图片使用序号 2～5，最多四页，合计不超过 QQ 的五条被动回复限制。
  原生图片正文不放 @ 标签，避免客户端显示原始标签；@ 提示失败时仍尝试发图，后台显示对应错误。
- 图片生成或发送失败会尝试文字摘要；若 QQ 账号尚未开放富媒体权限，需在平台完成相应配置。
- 数据过期或缺失会明确提示，接口错误不会当作“全部正常”。
- 回复不包含上游密钥、上游 URL、请求量、余额或原始错误正文。

## 群广告拦截

在 QQ 机器人设置中开启“群广告拦截”后，按以下规则处理已允许的 QQ 群：

- 收益诱导与扫码/注册引流同时出现，例如挖矿赚钱、首月收益宣传、扫码关注。
- 产品推广与代理招募同时出现，例如 AI 工具超市、创业项目、支持代理贴牌。
- 求购上游与私聊引流同时出现，例如 GPT 官方 key、找上游、报价后要求私聊。
- 明确命中自动撤回；疑似内容、举报/讨论广告的语境、OCR 失败等只记录。
- 单独提到 AI、模型、并发、倍率、价格、二维码不会自动撤回。
- 群主、管理员、后台检测管理员及“白名单成员 OpenID”均免于处理。角色不明的成员只记录。
- “全部仅记录”可暂停自动撤回，保留识别和记录。

需在**手机 QQ 群内**将机器人设为群管理员，并允许查看全部消息。本站“免 @ 查询”开关
与广告审核独立：即使没有启用免 @ 查询，广告审核仍可处理平台下发的群消息。
接口存在 2 分钟撤回时限，本实现保留 5 秒余量，超时不再尝试；失败会保留具体错误码。

图片采用服务器本地 Tesseract OCR（简体中文＋英文），不把群图片发送给 AI 模型。
最多读取每条消息前两张图片；仅从 QQ 附件域名下载，禁止重定向，校验实际连接 IP、5MB 文件上限和像素上限，
先解码为图片再编码为 PNG 交给 OCR。OCR 同时最多两项任务，消息审核最多 16 个在途任务，繁忙时可能跳过新消息。
每条消息处理最长 35 秒。未识别图片只记录，不据此自动撤回。

Docker 镜像增加了 `tesseract-ocr`、`tesseract-ocr-data-chi_sim`、`tesseract-ocr-data-eng`。
**后台仅替换程序的更新不会自动安装 OCR**。建议更新镜像并重建容器；现有 Alpine 容器可临时补装：

```sh
docker exec -u 0 sub2api apk add --no-cache tesseract-ocr tesseract-ocr-data-chi_sim tesseract-ocr-data-eng
```

容器名称按实际修改。后台会检查 OCR 和中英文语言包是否可用，缺失时显示提示。

记录保存于 Redis，最多最近 200 条，列表连续 7 天无新增后过期。只存群/成员/消息标识、时间、规则命中词和处理结果，
不保存原始聊天全文、图片或附件下载 URL。广告去重独立于查询的 5 秒冷却，不会因为前一条查询而跳过广告。
这是一套针对上述模式的规则识别，不是通用语义审核；未命中、文字被严重变形或 OCR 无法辨认的广告可能漏过。

## 生命周期与存储（机器人连接）

- 默认关闭。配置保存在已有 settings 表的 `qq_bot_config`，无需数据库迁移。
- AppSecret 使用现有 SecretEncryptor 加密，管理接口从不返回明文；留空保存会保留旧密钥。
  更换 AppID 时必须重新填写对应密钥。保持部署的加密主密钥稳定。
- Redis 选举一个实例连接 QQ，其他实例待命；失去租约或配置读取失败则断开。
- 配置每 5 秒刷新；禁用、凭据和范围变更会取消旧连接与处理任务，再按新配置连接。
- WebSocket 心跳超时会断开重连，优先恢复会话；无效会话重新鉴权。QQ 权限/封禁类拒绝显示错误，
  修正平台配置后可在本页停用并保存，再重新启用。
- Redis 原子去重保留消息编号 10 分钟，群内指令间隔 5 秒、实测间隔 60 秒；间隔内静默忽略。
  Redis 不可用时不执行命令。接受后崩溃可能不回复，但不会自动重复执行同一条实测命令。
- 最多并发处理 4 条命令；拥塞时断开并通过会话恢复重放，已处理消息会被去重。
- 实测超时不代表后台未执行，先查看后台记录再决定是否重试。

连接由服务器主动发起到 QQ 官方 API 和 WSS 网关。若后台始终重连，检查服务器出站网络、
AppID/AppSecret、QQ 服务器 IP 白名单和机器人使用权限。
本地测试不会调用真实 QQ 账号；实际登录和加群仍需在部署后联调。

### 后台能预览，群里只能收到文字摘要

这说明图片已经生成，失败在 QQ 上传或发送阶段，不需要重复安装字体。
先在群里发一次“渠道状态”，再点击后台“刷新连接状态”。失败状态会显示阶段、HTTP 状态码、
QQ `code` / `err_code` 和可用的 `trace_id`；服务器日志可搜索 `qq_bot: image delivery failed`。
记录这些诊断信息即可，不要分享 AppSecret、access token 或存储预签名 URL。

上传兼容当前官方 SDK 的 1 起始分片编号和早期文档的 0 起始编号；逐片确认时保留 QQ 返回的编号，
分片大小为 0 时使用整体分片大小，确认接口的空成功响应也视为成功。
只有真正收到富媒体消息 ID 才显示“状态看板图片发送成功”。
