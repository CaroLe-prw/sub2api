# 分组模型映射

在「分组管理 → 创建 / 编辑分组 → 分组模型映射」配置请求模型和目标模型，所有平台及混合分组均可配置。例如：

```json
{
  "model_mapping": {
    "gpt-5.6-luna": "gpt-5.6-terra"
  }
}
```

后续请求 `gpt-5.6-luna` 会在选择账号之前转换为 `gpt-5.6-terra`。账号无需声明支持 luna，只需能够服务 terra；发送给上游和查找用户计费价格均使用 terra。目标模型价格仍遵循现有分组定价、渠道定价、内置价格及倍率规则。

- 支持 OpenAI、Anthropic、Gemini、Antigravity、Grok、Kimi、智谱、DeepSeek、MiniMax 和混合分组配置。目标模型仍需由实际转发平台和入口支持。
- 文本入口覆盖 Responses（含 OpenAI WebSocket）、Chat Completions、Messages 兼容接口，以及 Anthropic / Gemini 的 token 计数接口。Grok 本地 token 估算保持原行为，不需要账号或模型价格。
- 混合分组先把原模型映射到目标模型，再按目标模型解析所属平台和混合路由。若混合路由继续将目标转为供应商名称，计价仍固定为分组目标模型。
- OpenAI 图片和 Grok 图片、视频、语音入口支持模型映射；媒体沿用现有图片规格、时长、字符数等计价方式。OpenAI Live 支持映射及日志归因，仍沿用现有不计费行为。
- 异步视频保存创建时的模型映射；后续查询完成并结算时使用这份映射，分组规则修改不会把在途视频改为其他目标模型计价。
- 精确匹配、区分大小写，不支持通配符；每次只应用一条分组规则，不递归映射。填写客户端实际传入的完整模型名。
- 命中分组规则时优先于渠道映射，并按分组目标模型计价。账号级规则仍可将目标模型转换为供应商模型 ID；账号里针对原模型 luna 的规则不会参与该请求。
- 文本目标价格不存在时使用现有缺失价格处理（告警并记录零费用），不会回退采用原模型或账号别名的价格。
- 未命中时保持现有路由行为。目标模型没有可用账号时按现有机制返回无可用账号，不回退至原模型。
- 使用记录保留原始请求模型、上游模型及映射链。模型白名单仍检查原始请求名，开启白名单时需要允许 luna。
- 每组最多 64 条规则，每个名称最多 200 字符。保存时清理首尾空白，拒绝空值、重复来源、通配符和控制字符。
- 删除全部规则并保存即可关闭。更新 API 省略 `model_mapping` 或传 `null` 保持原配置，传 `{}` 清空。
- 更新会使分组鉴权缓存失效。已建立的 WebSocket 连接使用建立连接时的分组配置；重新连接后使用新配置。

发布需要同时更新前后端，后端启动时执行 `239_group_model_mapping.sql` 数据库迁移。
