# 管理员错误请求诊断记录

管理员错误详情新增 `request_diagnostics`，用于对比客户端原始 JSON 请求和转换后的上游 HTTP 请求。每次上游失败记录账号 ID、HTTP 状态、上游请求 ID、请求快照和响应快照；返回客户端的错误响应继续显示在原有「诊断载荷」中。

采集随 Ops 监控开关启停。只在最终错误日志中保存快照，成功请求不保存正文。快照仅由管理员错误详情接口返回，不出现在错误列表或普通用户错误详情中。记录随原有错误日志一起过期清理，不提供请求重放。

## 范围和限制

- 入站正文最多在请求内缓存 64 KiB；超出上限时只保存省略原因和大小。
- 上游通过公共 HTTP 传输器采集。读取请求副本使用 `GetBody`，不消费实际发送的数据；没有可读副本时标记为未采集。
- 最近 4 次上游尝试保留配对快照，并注明省略的较早尝试数量。
- 单份脱敏正文最多 16 KiB，整份诊断 JSON 最多 192 KiB，均计入错误日志队列的字节预算。
- 仅保存可完整解析的 JSON。压缩的入站正文、非 JSON、读取失败、过大正文和不可读副本均保留明确的省略原因。
- 不缓存完整的成功状态流式响应。若 2xx 流稍后失败，可显示最后一次 HTTP 上游请求；流式错误内容仍以现有终态错误记录为准。
- WebSocket、插件自带传输或其他未经过公共 HTTP 传输器的路径，不能保证取得实际上游正文；不会伪造这些快照。

## 脱敏

不保存 Authorization、Cookie 等原始请求头，也不保存 URL 查询参数。JSON 中的凭据字段（API key、token、password、cookie 等）和二进制字段被替换；文本采用已有敏感信息清理规则。数值使用 `json.Number` 保留精度，`content` 的对象／数组形状保持不变，便于排查类型错误。

脱敏和限长发生在进入异步日志队列之前。任何带有省略或截断标记的快照都不是可重放的完整请求。

## 部署

迁移 `240_ops_request_diagnostics.sql` 向 `ops_error_logs` 添加可空的 JSONB 列。旧日志没有请求快照，无法补录。需部署包含后端迁移和前端展示的同一版本后，新增失败请求才会出现这些记录。
