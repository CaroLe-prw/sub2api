# Sub2API v0.1.171 更新日志

发布日期：2026-08-07

## 新增：API 密钥分组倍率保护

API 密钥现在可以设置“分组倍率保护阈值”，用于避免分组倍率上涨后继续产生超出预期的费用。

- 该功能默认关闭，阈值为 `0` 时不启用保护。
- 创建或编辑 API 密钥时，可以单独设置允许的最高分组倍率。
- 当前有效倍率高于阈值时，密钥会进入“临时不可调度”状态，并拒绝新的请求。
- 倍率回落到阈值或以下后，密钥会自动恢复调度，无需手动重新启用。
- 用户手动禁用的密钥不会因倍率回落而自动恢复。
- 用户配置了专属分组倍率时，优先使用专属倍率比较；未配置时才使用分组默认倍率。

例如，密钥保护阈值设置为 `0.08x`：倍率从 `0.08x` 降至 `0.06x` 时不受影响；上涨到 `0.09x` 时密钥会临时停止调度；回落到 `0.08x` 后自动恢复。

## 密钥列表提示

`/keys` 页面会直接显示密钥的动态调度状态。超过保护阈值时，列表中会标记“临时不可调度”，并展示当前倍率与阈值，例如：

```text
当前 0.09x > 阈值 0.08x
```

该状态不会修改密钥原有的手动启用/禁用设置，便于区分用户主动关闭与倍率保护触发的临时暂停。

## 调度与缓存

- 标准 API 认证和 Gemini API 认证均已接入倍率保护。
- 用户专属倍率更新后，会立即失效该用户相关 API 密钥的认证缓存，使新倍率及时参与判断。
- 认证快照版本已更新，升级后不会继续使用旧倍率快照。

## 账号复制

- 复制 OpenAI API Key 账号时，会保留 NewAPI 倍率来源、Base URL、UID、加密访问令牌、倍率校准系数和低余额提醒配置。
- 副本不会继承上次同步时间、同步结果、解析分组、余额或探测快照，而是以“尚未同步”状态重新开始。
- 复制后的账号仍默认暂停调度，管理员确认配置后再手动启用。

## 账号列表

- 原“调度成本 / 上游余额”已拆分为“调度成本”和“上游余额”两列，两列均支持独立排序。
- 两列都保留刷新按钮；点击任意一个都会执行同一次上游探测，并同时更新调度成本与余额。
- 上游余额按数值排序，缺失或无效的余额始终排在有效余额之后。

## 上游倍率同步

- “Sub2API 探测”现在会始终同步上游声明的基准倍率，不再提供单独关闭倍率同步的开关。
- 新建 API Key 账号默认启用 Sub2API 探测与倍率同步，避免调度成本和持久化账号倍率不一致。
- 升级时会自动为已有的 Sub2API 探测账号开启倍率同步；使用 NewAPI 倍率来源的账号不受影响。

## 升级说明

- 新增数据库迁移 `196_add_api_key_max_group_rate_multiplier.sql`。
- 新增数据库迁移 `197_enable_upstream_rate_sync_with_probe.sql`。
- 现有 API 密钥的保护阈值默认为 `0`，升级不会自动停用任何现有密钥。
- 倍率在会话进行期间上涨并超过阈值时，后续请求可能被暂停。用户需要登录后台调整保护阈值或等待倍率回落。
