# 糖果检测数据清理

糖果检测运行器启动后自动开启清理，不依赖分组是否启用自动检测，也不受运维日志清理开关影响。

- **时间**：按应用配置的时区，每天 **03:30** 执行；启动时额外补清一次。
- **保留窗口**：清理时删除超过 **24 小时**的检测历史及答案正文；最近历史仍最多保留 **12 条**。每次新检测写入前也淘汰过期历史，避免并发检测把刚清理的旧答案写回来。
- **保留状态**：累计通过/失败/接口异常计数、最近有效结论、连续失败次数、调度阻断标志、分组检测时间、账号手动调度开关和其他配置不清除。清理不会使异常账号恢复调度，也不会让所有分组立即重新检测。
- **测试日志**：分批删除超过 24 小时、带账号 ID、`component = service.account_test` 且 `message = account_test.failed` 的测试失败日志。这类日志由糖果检测与连通性测试共用，因此两类旧测试失败日志都会清理。业务请求日志、计费记录及审计日志不在清理范围内。
- **执行保护**：复用现有跨实例锁；每批处理 100 条、单轮最多 10 分钟。按账号 ID 翻页，使用比较后更新保护并发写入；不重写未变化的数据，不发送调度失效事件。单条损坏的历史记录会跳过并记录账号 ID，避免阻塞其他账号。
- **停机**：随运行器取消正在执行的清理，并等待退出。失败或超时会记录日志，下次定时触发或启动时继续清理。

保留窗口、每日时间和批大小定义在 `backend/internal/service/account_candy.go`、`backend/internal/service/candy_test_cleanup.go`，目前不新增管理界面配置。

发布新版后生效，无需执行数据库迁移。清理是逻辑删除/更新；PostgreSQL 会按自身的 autovacuum 策略回收空间供后续写入复用，文件大小不一定立即下降。该任务不执行锁表的 `VACUUM FULL`。
